jeremylongshore.com Hub Rebuild — Architecture

Target state after the rebuild: the current Ruby static build is replaced by a Next.js 15 standalone server running in Docker on the production VPS, behind the shared Caddy ingress. Every dynamic section — GitHub stars, contributions heatmap, merged external PRs, the writing feed, per-post view counts — is rendered server-side via ISR; the visitor's browser only ever talks to Caddy and the analytics beacon.

Component details

Serving path — Caddy → hub

  • Caddy is the VPS-wide shared ingress: caddy validate then systemctl reload caddy — never restart.
  • The site block becomes a reverse_proxy to 127.0.0.1:3000, replacing the static file_server.
  • The hub runs as a Next.js 15 standalone server in Docker, exposing /api/healthz for the deploy gate.
  • Visitors only ever reach Caddy; the app container is never published beyond loopback.

ISR data layer

  • All third-party data is fetched server-side during ISR revalidation — never from the browser.
  • GitHub REST (stars), GraphQL (contributions calendar), and Search (merged PRs) revalidate on a 6h TTL.
  • The startaitools.com RSS writing feed revalidates on a 1h TTL.
  • Fetchers fail loudly: a failed revalidation keeps last-good data and raises a build/health alarm — no silently empty sections.

Analytics — Umami

  • Reuses the existing Umami stack on the VPS; no new analytics service is introduced.
  • The browser sends the beacon to the analytics domain directly (dashed edge) — the only non-Caddy browser call, and it is first-party infrastructure.
  • The hub reads per-post view counts from the Umami API over the VPS-local network on a 15m TTL.

CI/CD pipeline

  • GitHub Actions runs the build + test gate only — no image build or registry push happens in CI.
  • Deploy rides Tailscale OIDC into a force-command SSH session (command-restricted key) to the VPS.
  • The VPS-side deploy script does git fetch + docker compose build + up -d — the image is built on the VPS.
  • Actions then smoke-checks /api/healthz; failed runs notify Slack #prod-deploys, healthy runs stay quiet.
  • A name-leak gate runs before every commit — the reference site's owner is never named in this repo.

Design system posture

  • The token layer keeps a neutral base palette; color appears only as an interaction reward — hover states and focus rings.
  • App Router pages compose from a small component library driven by those tokens.
  • No client-side data fetching means no loading spinners for core content — pages arrive fully rendered.

Failure posture

  • Every external fetch is wrapped: failure → serve last-good cached payload + alarm.
  • The deploy gate refuses to call a run green unless /api/healthz passes after compose up -d.
  • Caddy reload (not restart) keeps the other VPS stacks untouched during config changes.
